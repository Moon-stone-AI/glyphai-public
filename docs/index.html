How it works

Five sources, one language

The logs already sit on the servers being sold. We read them before decommissioning, translate every vendor's wording into one set of concepts, and tie each event to a GPU by its PCIe address. Nothing is installed on the servers: one read-only script gathers the logs into an archive you review first, and the analysis runs offline on the copy.

What it is not

Stated limits

  • History, not a forecast. The score describes what happened to a card. It is not a probability that the card will survive a given time.
  • Tested on synthetic fleets. Real logs differ; each new fleet starts with tuning its vocabulary.
  • Starting weights. Set from operations practice and to be calibrated on real failure data.
  • No logs, no history. A card whose logs were wiped can only be graded by testing.

    Security & compliance

    Built around data minimisation

    The GlyphAI collection process is designed to give your security team full control: the collector is open source, read-only by default, makes no network connections, and masks identifying data before an archive is created. Nothing leaves your environment until you review and send it.

    • Read-onlyInstalls nothing, changes no configuration
    • No networkNo connections, no open ports
    • Masked by defaultHostnames, IPv4/IPv6, MACs, serial numbers
    • Open sourceAuditable before execution
    Is the collector safe to run on production or decommissioned servers?

    Yes, in its default mode. The collector only reads existing diagnostic data:

    • the kernel log (journalctl -k, or dmesg as a fallback);
    • the BMC system event log through ipmitool sel elist;
    • GPU state through nvidia-smi -q, PCIe link state from /sys/bus/pci, and DCGM GPU discovery.

    It installs no software, changes no hardware or system configuration and starts no services. Its only disk writes are a temporary working directory, removed on exit, and a single .tar.gz archive in the directory where it is run. Root privileges are recommended so that the kernel and BMC logs can be read in full.

    Exception: the optional --diag flag runs NVIDIA DCGM active diagnostics, which place load on every GPU. It is off by default and should be used only on idle, drained nodes.

    Can our security team review the collector before it is executed?

    Yes. The collector is a single shell script of about 160 lines with no compiled components. The full source is published at github.com/Moon-stone-AI/glyph-fleet-rca, and each command it runs is listed in its header.

    Which identifiers are masked, and which are retained?

    Masking is enabled by default and is applied on the server before the archive is created:

    • Hostname is replaced with node-<hash>, derived from a one-way SHA-256 hash;
    • IPv4, IPv6 and MAC addresses are masked;
    • Serial numbers, board part numbers and Dell service tags are replaced with REDACTED.

    Masking applies to every text file in the archive, including vendor BMC exports (iDRAC, XCC, iLO) supplied through the --bmc option. Original export files are copied, never modified.

    Retained by design: GPU UUIDs and PCIe addresses, because they link a health history to the physical card being bought or sold.

    Your review is recommended for: files added to the archive by hand after it is built, which are not masked, and serial numbers held in unlabelled CSV columns, which are not recognised automatically. Masking can be disabled with --no-redact; we do not recommend it.

    Does the process require network access, firewall changes or open ports?

    No. The collector makes no network connections, inbound or outbound, opens no ports and requires no change to firewall rules or host security configuration. The archive is transferred by you, through a channel your organisation approves.

    How is the archive handled after it is delivered?
    1. Review. You inspect the archive locally before release (tar -tzf lists its contents).
    2. Processing. Analysis runs offline on a copy of the archive using GlyphAI's own software. Logs are not passed to third-party services.
    3. Purpose limitation. Logs are used solely to produce your report.
    4. Disposal. Source logs are deleted within 30 days of report delivery, or earlier on request. Written confirmation of deletion is available on request.
    Can the logs contain personal data, and how is GDPR addressed?

    Infrastructure logs rarely contain personal data, but kernel logs can include user or process names. GlyphAI is based in Ireland and processes logs in the EU. Where your logs may contain personal data, a data processing agreement can be put in place before any transfer.

    Does GlyphAI hold SOC 2 or ISO 27001 certification?

    Not at present. We support your vendor security review with the public source code of the collector, this documentation, and a written data-handling agreement. Contact vitali.demille@glyphai.ie to request a security questionnaire response.
